Go · Bubble Tea · SQLite · ffmpeg

A terminal-first anime app: search, stream, download, resume. The interface stays keyboard-driven, the player stays a real video player, and every provider sits behind one small adapter contract. SQLite makes the app feel continuous instead of forgetting everything when it exits.

Shipping in v1 the current build pass

Home dashboardbuild

One screen with a search box, continue-watching rows, recent searches, and library stats. No empty prompt-only start.

  • resume rows with position / duration
  • recent queries with relative time
  • downloaded count + library size
Search + historybuild

Search the active provider, keep the query in SQLite, and show result metadata the site already exposes.

  • title, type, sub/dub, status badges

  • query history survives restarts
Episode browserbuild

Episodes are a first-class list with state from the database, plus a detail panel for the selected episode.

Play onlinebuild

Resolve the HLS stream and hand it to mpv with a title, referer, subtitles, and the saved start position.

  • mpv OSC: seek, pause, volume, fullscreen
  • resume from last position
  • ffplay fallback with keyboard controls
Downloadsbuild

Download one episode, the rest of a season, or a whole season through ffmpeg, with a visible queue.

  • per-episode progress, speed, ETA
  • cancel + retry; skip existing files

SQLite librarybuild

One database in the platform app-data directory. Search history, watch progress, and the download index.

  • WAL mode + indexes
  • safe concurrent reads while ffmpeg runs
  • -db override for testing/portable use
Provider adaptersbuild

Gogoanime is the only provider in v1, but the app already speaks through the contract. New sites do not touch the TUI.

  • Name, Search, Episodes, Stream
  • provider-specific parsing stays in its package
  • base URL override for mirrors
Downloaded librarybuild

Browse the download root without the network. Local files play in mpv with resume and sidecar subtitles.

It should read as an app, not a script: proper title, adaptive layout, consistent panels, and clear failure states.

An IBM Carbon dark palette plus a ready-to-apply IBM Plex Mono setup. The terminal owns the font; the repo ships the rest.

Next after v1 is stable

Quality pickernext

The HLS master already exposes 1080p / 720p / 480p. Add a per-download choice instead of always taking the best variant.

Provider switchernext

A provider picker in the header and a combined search view. The adapter contract is already in place.

Pause / resume downloadsnext

ffmpeg does not pause cleanly. This needs segment-level downloading or a resumable downloader, so it is deliberately deferred.

Skip intro / outronext

MegaPlay already returns intro/outro timestamps in the sources JSON. Wire them into mpv chapters or a skip key.

Next-episode autoplaynext

When mpv exits near the end, offer the next episode and keep the watch session moving.

Library managementnext

Open folder, disk usage, delete an episode, and verify files that disappeared outside the app.

Concurrent downloadsnext

Two or three episodes in parallel, with a configurable queue and per-slot progress.

Subtitle selectionnext

MegaPlay lists multiple caption tracks. Expose English/other tracks and pass the choice to mpv.

Search paginationnext

WordPress search returns page 1 only today. Add “load more” without changing the results screen model.

Playback & media controls

primary player
mpv — on-screen controls (OSC), subtitles, hardware decode, title, referer, --start resume.
v1
resume
mpv IPC reports time-pos every 5 s; the TUI writes it to watch_progress. Reopening starts at the saved position.
v1
fallback
ffplay — used only when mpv is absent. Keyboard controls: space pause · ←/→ seek · ↑/↓ volume · f fullscreen · q quit. Resume works; live progress saving does not.
limited
why external
A terminal cannot render video well. mpv gives real controls, audio, subtitles, and hardware decoding without building a player.

Deliberately not doing

Browser automationno

The source is plain HTTP + one AES key. A headless browser would add hundreds of MB and a permanent maintenance problem. If a future provider truly needs JS, that adapter can own it.

In-TUI video surfaceno

Embedding video in a terminal is a worse experience than mpv. The TUI owns discovery and queueing; mpv owns playback controls.
